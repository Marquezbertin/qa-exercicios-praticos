Análise de Defeitos — create_order

Após análise criteriosa do código frente aos requisitos, identifiquei 6 defeitos:

Defeito 1 — Falta de verificação de quantidade inteira
Problema: O código verifica apenas quantity <= 0, mas não verifica se a quantidade é um número inteiro. Quantidades como 1.5 ou 0.3 são aceitas.

Onde: Linha if quantity <= 0: dentro do loop.

Quando acontece: Sempre que um item possuir quantidade não inteira (float).

Exemplo de entrada:

items = [{"product_id": "P1", "quantity": 1.5}]

Esperado: Deveria lançar ValueError, pois o requisito 2 exige "quantidade inteira maior que zero".
Obtido: O pedido é criado normalmente com quantity = 1.5.

Defeito 2 — Estoque alterado antes da validação completa de todos os itens
Problema: O estoque é decrementado dentro do loop, item a item. Se um item posterior falhar na validação, o estoque dos itens já processados já foi reduzido — violando o requisito 5.

Onde: Linha inventory[product_id] -= quantity dentro do loop for item in items.

Quando acontece: Quando há múltiplos itens e pelo menos um item posterior falha na validação (quantidade inválida ou estoque insuficiente).

Exemplo de entrada:

inventory = {"P1": 5, "P2": 1}
items = [
    {"product_id": "P1", "quantity": 3},
    {"product_id": "P2", "quantity": 2}  # estoque insuficiente
]

Esperado: Estoque de P1 permanece 5 (nenhuma alteração, pois a validação falhou para P2).
Obtido: Estoque de P1 é reduzido para 2, e depois o ValueError é lançado para P2 — o estoque ficou corrompido.

Defeito 3 — Subtotal calculado com valor de estoque já decrementado
Problema: O código faz inventory[product_id] -= quantity antes de calcular o subtotal com subtotal += inventory[product_id] * quantity. Assim, a multiplicação usa o valor de estoque restante (após a compra), não o valor original. Mesmo que inventory[product_id] representasse o preço unitário, o decremento corrompe esse valor antes da multiplicação.

Onde: Linhas inventory[product_id] -= quantity seguida de subtotal += inventory[product_id] * quantity, dentro do loop.

Quando acontece: Sempre, para qualquer pedido com pelo menos um item.

Exemplo de entrada:

inventory = {"P1": 10}  # preço unitário = 10
items = [{"product_id": "P1", "quantity": 3}]

Esperado: Subtotal = 10 × 3 = R$ 30,00.
Obtido: Após decremento, inventory["P1"] = 7 → Subtotal = 7 × 3 = R$ 21,00.

Defeito 4 — Condição do cupom SAVE10 usa > em vez de >=
Problema: O requisito 4 diz que o desconto se aplica quando o subtotal for maior ou igual a R$ 100,00. O código usa subtotal > 100, excluindo o caso de igualdade.

Onde: Linha if coupon == "SAVE10" and subtotal > 100:.

Quando acontece: Quando o subtotal é exatamente R$ 100,00 e o cupom "SAVE10" é utilizado.

Exemplo de entrada:

# Supondo subtotal calculado corretamente = 100.00
coupon = "SAVE10"

Esperado: Desconto de R$ 10,00 (10% de 100).
Obtido: Desconto de R$ 0,00 — cupom não é aplicado.
